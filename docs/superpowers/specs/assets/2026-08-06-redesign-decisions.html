The reframe

A “park” was two different things wearing one word

Every awaiting-* status conflated the pipeline cannot compute with a human has not signed. It is almost always the second — and the data model was already built for the first.

Was
  • awaiting-physics — Dosing stops because DetectionFloor.Compute refuses without a measured XRF background.
  • awaiting-RE — Regulatory stops for the expert's determination.
  • awaiting-VP — Decision stops at the final gate.
  • awaiting-samples — stops for the client.
  • awaiting-confirmation — stops before anything runs at all.
Now
  • Dosing runs and emits a floor of kind estimate instead of measured. The type already exists — BoundKinds models exactly this, and the ppm chart already draws an estimated end differently from a known one.
  • Regulatory runs and writes ProposedDetermination. The analysis is finished; the ruling is outstanding.
  • Decision assembles the full recommendation and holds at complete, unsigned.
  • Deleted with decision 02.
The line that does not move

“Runs end to end” must never come to mean “signs itself.” There is already an auto-approve path in the codebase, and the UI renders it as an alarm in the largest type on the screen — for good reason. The terminal state of an unattended run is complete, unsigned, not done. Both hard gates stay human, or the product becomes a machine that recommends taggants into food-contact plastic with nobody in the loop.

Its corollary: a provisional number must look provisional everywhere — matrix column, ppm chart, and the Excel export alike. A cell reading “60 ppm” with no provenance mark is the dangerous version of this feature.

What each new fact invalidates

You are right that a background measurement has no bearing on a regulatory verdict. The rule that follows is data dependency, not pipeline position — and the writable-field allow-list that already exists (IntakeAnswers.AllowedFields) turns out to be exactly the list that needs blast radii declared beside it.

Keep this table next to the allow-list, as code — a writable field with no declared blast radius should fail the build, the same discipline that made the parked-status family a compile error rather than a review problem.

Amendments

How the operator adds what the customer just told them

The mechanism is already built and already correct — it simply has no home in the UI once Intake stops being a phase. IntakeAnswers.Patch is an allow-list: operator-known product facts are writable through chat, and the physicist's measured data is refused by construction, by name, with an explanation aimed at the model. That is the amendment API.

1
The operator says it, on Overview

No form. The intake agent has a composer on the project's Overview screen, beside the brief it wrote. “Customer confirmed they're shipping to Japan as well.”

2
The agent records it as an amendment

Through record_answer, onto components.bottle.markets. Appended to an amendment log with when, what changed, and the operator's stated reason — the same instinct as a Learned Conclusion: the “why” is the point, not the value.

3
The table says what it costs before anything runs

markets → Regulatory, Sign-off — so Discovery's twelve candidates stand, and only the verdicts are stale.

!
If a signature is in the blast radius, stop and ask

An unsigned project just reruns — nothing waits, per decision 08. But if the regulatory gate is already signed, that rerun voids a human signature, and the code already voids ApprovedAt and ApprovedBy as a pair. Silently un-signing someone's approval is not a thing software should do quietly. This is the one place a confirmation earns its interruption.

5
The rerun reports its diff

Regulatory reran · 2 verdicts changed · Eu now fails the element gate — because a rerun that silently mutates a record the operator has already read and reasoned about is worse than no rerun at all.

What this does to the dashboard

It answers the question I asked last round, so ignore it: grouping by “who are we waiting on” is dead, because nobody is waited on. The buckets that survive are about state of belief, not state of queue — needs your signature, provisional (running on estimates; real data would sharpen it), and closed. Which is a better dashboard than either version we discussed.

Agreed too that the dashboard's whole look gets redone rather than patched — that's a separate pass, and it is now downstream of this model rather than upstream of it.
